# ポートフォリオ企画メモ

README の「僕という人間がすべて詰まったポートフォリオ」を、これからエンジニアになる本人の開発経験が伝わる体験にする。出発点は「人と話すのが好き」「文字を少なく、空間を触って回りたい」「いろいろな僕と話せたら面白い」。

## 仮案「いろんな僕に会いに行く」

一つの空間に、開発中の異なる場面にいる本人がいる。来訪者は気になった本人に近づき、差し出されたものに触れる。最初に見えるのは、人の動きと触れられるもの、短い操作ラベル。会話は短い一往復で始まり、本人の声を使う場合はタップで再生し、同じ内容を字幕でも読める。

- **見せたい僕**がアプリの操作を一つ見せ、来訪者に操作を渡す。実際のアプリや動くデモを触れる。
- **考えている僕**が同じアプリの実際の判断を一つ見せる。当時の選択肢を触って違いを比べ、本人が選んだ理由を短く聞ける。
- **試している僕**が、学習中に書いたコードや小さな試作を手渡す。技術の名前から、何を試したかまでたどれる。

呼び名と場面は仮。本人が普段どんなふうに作品を人に見せるか、実際のエピソードから動きや台詞を決める。

## エンジニアとしての実績

作品の詳細は必要なときに開ける。アプリ名、目的、自分が担当したこと、使用言語・技術、デモやソースへのリンクを載せる。触れた言語には「作品で使用」「小さな試作で使用」「学習中」など、実際の使用経験が分かる短い説明を添える。最初の画面から「作品・技術」へも直接進める。

## 最初の試作

見下ろせる小さな空間で「見せたい僕」と「考えている僕」に会い、同じアプリを二つの角度から体験する。アプリ一つ、触れる操作一つ、当時の判断一つで作る。画面をタップして出会える形から試し、空間の表現は操作してから決める。

素材は、アプリの名前、最初に人に触ってほしい操作、そのアプリで迷って決めたこと、使った言語。その操作を人に渡すときに普段なら何と言うかも、本人の言葉で残す。

友人一人に説明なしで触ってもらい、「何を作った人だと思った？」「二人のうち、どちらの場面を覚えている？」と聞く。アプリと本人の判断の両方が伝わったかで見直す。

## 最初の作品と、AIを使った制作の記録

制作中の Web ゲームと卒業制作の Web サービス「Umoja」は、制作中のプロジェクトとして記録する。AIへの指示や作り直しのうち、実際に何を試し、どこを見て採用や修正を決めたかが分かる場面を拾う。コードの生成を任せた範囲と、自分が決めて動作を確かめた範囲は、具体的な作業として書く。

最初の展示の候補は、ポートフォリオ自体の小さな一場面。画面上の「僕」に近づくと、こちらを向いて手を振る。離れると元の動きに戻る。近づいたことをどう判定し、見た目をどう変えるかを本人がコードで扱う。AIには仕組みの説明や詰まったときのヒントを頼める。まず変える箇所と期待する動きを本人が決めて、一か所書き換え、ブラウザで結果を確かめる。分かったことを自分の言葉で一行残す。

この場面が最初の展示として使えるかは、本人が「ここはこう動かしたかった」と操作しながら説明できるかで確かめる。
